# LLM System Design — Interactive Lab (LangChain + Streamlit)

A hands-on companion to the *LLM System Design* ebook. Every core system from the
book is reimplemented with **LangChain** and made **runnable and testable in a
Streamlit UI** — with your local **Ollama** models (`llama3.1` + `nomic-embed-text`)
as the real backend, and a deterministic **offline** fallback so it runs anywhere.

## What's inside

| Page (UI) | System | Module | Book chapters |
|---|---|---|---|
| 🔀 Model Routing & Cascade | LCEL routing by difficulty + telemetry | `routing.py` | 2–3 |
| 📚 RAG | LangChain vector store, retrieval, cited answers | `rag.py` | 13–16 |
| 🤖 Agent & Tools | ReAct loop over LangChain tools (sandboxed) | `agents.py` | 17–19 |
| 🛡️ Guardrails & Red-Team | Input/output screening + catch-rate | `guardrails.py` | 21–23 |
| ⚡ Semantic Cache | Embedding-similarity response cache | `caching.py` | 32 |
| 🎯 Recommendation | Collaborative filtering + cold-start | `recommend.py` | 38 |
| 📊 Evaluation Harness | RAG eval + LLM-as-judge, pass-rate/cost | `evaluation.py` | 27–29 |
| 🧰 Platform Modules | Every public callable in `llm_platform`, grouped by chapter, with an auto-generated input form | `platform_bridge.py` | 1–50 |
| 🌱 Seed Data | Generate/inspect all datasets | `seed.py` | 6 |
| 🧾 Source Code Browser | Read any module's source in the UI | — | — |
| ✅ Run Tests | Execute the offline `pytest` suite | `tests/` | 45 |

Backend selection lives in `config.py`; telemetry (tokens/latency/cost) in `telemetry.py`.

The first eight pages **re-implement** their system with LangChain and real models.
The **🧰 Platform Modules** page is different: it calls the book's reference
implementations in `project/llm_platform/` directly. It introspects each module,
derives an input form from the real signature, and runs the function — so every
chapter's code is reachable from the UI, not just the eight that have a bespoke
page. Adding a function to `llm_platform` makes it show up here with no UI work.

## Quick start

```bash
cd lab
pip install -r requirements.txt

# (optional but recommended) real models via Ollama:
#   install Ollama from https://ollama.com, then:
ollama pull llama3.1
ollama pull nomic-embed-text
ollama serve            # if not already running

# generate the seed data (also do-able from the UI)
python -m llm_lab.seed

# launch the UI
streamlit run app.py
```

Open the browser tab Streamlit prints (default http://localhost:8501). Pick a
**backend** and a **system** in the sidebar, run the demo, and read the source.

### Backends

- **`ollama`** — uses `ChatOllama(llama3.1)` and `OllamaEmbeddings(nomic-embed-text)`
  on your machine. Set `LAB_BACKEND=ollama` or pick it in the sidebar.
- **`offline`** — a deterministic `OfflineChatModel` + hash embeddings; no server,
  no GPU, no API key. Used automatically when Ollama isn't reachable.
- **`auto`** (default) — Ollama if reachable, else offline.

Override models with env vars: `LAB_LLM`, `LAB_EMBED`, `OLLAMA_BASE_URL`.

## Testing

```bash
LAB_BACKEND=offline python -m pytest -q      # deterministic, no server
```

The suite exercises routing, RAG retrieval + citations, the agent tool loop,
guardrails + red-team, the semantic cache, evaluation, and the recommender.

## How the non-functional requirements show up

- **Latency** — every page reports per-request latency (ms); routing/RAG measure the
  LCEL chain, the agent traces each tool step.
- **Throughput / cost** — token estimates and estimated cost per request are shown;
  the semantic cache demonstrates collapsing paraphrases into one call.
- **Quality** — the Evaluation page runs the eval set with faithfulness and an
  LLM-as-judge score; the guardrails page reports red-team catch rate.

## Notes

- This lab is the *interactive* companion. The ebook's reference project (dependency-free,
  155 tests) lives in `../project/`; this lab layers LangChain + a UI on the same ideas.
- With Ollama running, answers are generated by `llama3.1` and retrieval uses
  `nomic-embed-text`, so semantic cache hits and RAG relevance are much stronger than
  in offline mode.
